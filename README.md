### Общая информация

ExploreWithMe Plus представляет собой переработанный вариант монолитного приложения ExploreWithMe, преобразованный в микросервисную архитектуру. Целью работы является повышение масштабируемости, отказоустойчивости и гибкости системы за счет разделения монолита на независимые сервисы, взаимодействующие между собой через REST и механизмы сервис-обнаружения.

В проекте используются следующие технологические компоненты:

Spring Boot

Spring Cloud OpenFeign

Eureka Discovery Server

Config Server

Spring Cloud Gateway (API Gateway)

PostgreSQL (общая база данных)

Архитектура системы

Система разделена на отдельные микросервисы, каждый из которых отвечает за строго определенную доменную область. Все микросервисы используют общую реляционную базу данных, однако каждый из них обслуживает собственные таблицы, определенные в отдельных schema.sql.

### Основные сервисы
1. event-service

Сервис отвечает за основную доменную логику приложения:

управление событиями (events),

управление категориями (categories),

управление подборками событий (compilations),

интеграцию с сервисами комментариев и заявок.

Содержит внутренний API /internal/events, обеспечивающий доступ к объектам событий для других сервисов.

2. user-service

Сервис управления пользователями:

создание пользователей,

удаление пользователей,

получение информации о пользователях.

Содержит внутренний API /internal/users/{id}.

3. request-service

Сервис обработки заявок на участие в событиях:

создание, отмена и получение заявок,

изменение статуса заявок инициатором события.

Хранит только идентификаторы eventId и requesterId.
Использует внутренний API main-service для проверки публикации событий и авторства.

Содержит внутренний API /internal/requests/....

4. comment-service

Сервис работы с комментариями:

создание, обновление и удаление комментариев,

модерация комментариев администратором,

получение комментариев по событиям.

Использует внутренний API main-service и user-service для проверки корректности данных.

5. gateway-service

API Gateway служит единой точкой входа в приложение.
Обеспечивает маршрутизацию запросов к соответствующим сервисам согласно конфигурации:

/admin/users/** → user-service

/requests/** → request-service

/events/*/requests/** → request-service

/** → event-service

6. config-server

Сервис централизованного хранения конфигураций.
Конфигурации всех сервисов находятся в Git-репозитории и автоматически подгружаются при запуске.

7. eureka-server

Сервис обнаружения.
Все микросервисы регистрируются в Eureka и взаимодействуют друг с другом по логическим именам (lb://service-name).

8. stats-service

Сервис сбора статистики:

запись фактов посещений (/hit),

выдача агрегированных данных (/stats).

Используется event-service для учета просмотров событий.

### Внутренний API (internal API)

Для взаимодействия между микросервисами используются внутренние эндпоинты, не доступные извне.

event-service

GET /internal/events/{eventId}
Возвращает полное описание события, включая информацию о пользователе-инициаторе и количестве подтвержденных заявок.

user-service

GET /internal/users/{id}
Возвращает краткие сведения о пользователе.

request-service

GET /internal/requests/event/{eventId}/count/{status}
Возвращает количество заявок данного события в указанном статусе.

comment-service

Предоставляет внутренние методы получения и проверки существования комментариев, если требуется взаимодействие с main-service.

### Внешний API

Внешние REST-эндпоинты полностью соответствуют спецификации API группового проекта ExploreWithMe, включая:
публичные методы работы с событиями,
пользовательские методы работы с комментариями и заявками,
административные методы управления сущностями.


###  Взаимодействие сервисов

Взаимодействие реализовано через:

Eureka Discovery Server

OpenFeign-клиентов

внутренние REST-эндпоинты

API Gateway для наружного трафика

### Основные зависимости:

event-service обращается к user-service и request-service,
request-service обращается к event-service для получения информации о событиях,
comment-service обращается к user-service и event-service,
stats-service используется event-service для учета просмотров.

### База данных

Используется общая база PostgreSQL.
Каждый микросервис содержит свой собственный schema.sql,
что обеспечивает изоляцию данных на уровне логики и структуры,
даже при использовании общей базы.
